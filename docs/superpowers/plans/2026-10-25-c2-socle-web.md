# C2 — Socle web (Next.js + Prisma + Auth.js) — Plan d'implémentation

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal :** l'application web du prototype. Un chercheur se connecte, crée des projets et des études, renseigne leurs paramètres (méthodes, limites LOD/LOQ, contrôles qualité résumés, référence, pseudonymisation) et consulte le journal d'audit. Toutes les écritures sont tracées, et la base refuse toute modification du journal. `docker compose` lance la base et le moteur.

**Architecture :** nouveau dossier `web/`, une application Next.js (App Router) en TypeScript strict.
- Prisma pour PostgreSQL.
- Auth.js (identifiants, sessions JWT de 8 h).
- Server Actions pour les formulaires, services serveur dans `web/src/server/`.
- Le client du moteur est généré depuis `engine/openapi.json`. Toute règle scientifique est validée par le moteur (nouvelle route `/context/validate`) ; aucune n'est réécrite en TypeScript.
- Interface en français avec Tailwind CSS et shadcn/ui.
- Tests : Vitest, avec une instance PostgreSQL temporaire (`embedded-postgres`) pour les tests de base de données.

**Tech Stack :** Node 24, Next.js 16 (App Router, `proxy.ts`), React 19, TypeScript strict, Prisma ORM (version stable courante, client généré), PostgreSQL, Auth.js v5 (`next-auth`), Zod, Tailwind CSS v4, shadcn/ui, openapi-typescript, Vitest, Testing Library, embedded-postgres, tsx. Python (moteur) pour la tâche 3.

**Spec :** `docs/superpowers/specs/2026-10-25-prototype-studio-design.md` (§2, §3 contrat, §4 modèle, §6 écrans, « Comptes et accès », « Tests et audit »).

## Global Constraints

- Tout le code web vit dans `web/`. Commandes depuis `web/` : `npm run lint`, `npm run typecheck`, `npm test` (Vitest), `npm run build`. Les commandes Python restent celles de C1 (`.venv/Scripts/python -m pytest …`).
- **Aucune règle scientifique en TypeScript.** Unités, LOD ≤ LOQ, nature des données ou références obligatoires sont validées par le moteur (`/context/validate`, tâche 3). Le TypeScript ne valide que la forme : champ requis, nombre lisible, longueur.
- **Journal d'audit en ajout seul.** Chaque écriture métier crée un `AuditEvent` dans la même transaction (`prisma.$transaction`). Un déclencheur SQL refuse `UPDATE` et `DELETE` sur `AuditEvent`.
- **Le navigateur ne voit jamais le moteur.** Tout appel au moteur passe par du code serveur (`import "server-only"`). `ENGINE_URL`, `ENGINE_SECRET`, `AUTH_SECRET` et `DATABASE_URL` viennent de l'environnement ; `web/.env.example` les documente, sans valeurs réelles.
- **Accès :** toute page sauf `/connexion` exige une session (`proxy.ts`, puis une vérification dans chaque action serveur). Un seul laboratoire : tout utilisateur actif voit et modifie tout.
- **Langue :** textes visibles en français, `<html lang="fr">`, nombres et dates au format français (`Intl`, `fr-FR`).
- **Données :** jamais de suppression d'étude, de projet ou d'événement. Une étude archivée est en lecture seule (serveur et interface).
- Versions exactes figées par `package-lock.json`, à committer.
- Fichiers ignorés par Git : `web/node_modules/`, `web/.next/`, `web/.env*` (sauf `.env.example`), `var/`, `web/test-results/`.
- Commits conventionnels terminés par `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.

## Liste de contrôle de l'interface (ui-consistency)

Constat : le dépôt ne contient **aucune interface** (aucun `.tsx`, `.css`, `package.json` ni thème). Il n'y a donc aucune page de référence ni famille de pages à compter. Ce qui suit est une **proposition de l'équipe technique**, approuvée par délégation du fondateur ; les pages de C3, C4 et C5 à C7 s'y conformeront.

- **Thème :** un seul endroit, `web/src/app/globals.css` (variables CSS du thème shadcn/ui : couleurs, rayon, espacements). Palette sobre : neutre ardoise, accent bleu, `destructive` rouge, `warning` ambre ajouté au thème. Aucune couleur ni taille écrite en dur dans les pages.
- **Composants de base :** ceux de shadcn/ui, copiés dans `web/src/components/ui/` : button, input, label, select, textarea, table, tabs, dialog, alert, badge, card, form, checkbox, sonner.
- **Composants partagés de l'application** (`web/src/components/app/`), créés une seule fois et utilisés par toutes les pages :
  - `AppShell` : en-tête avec le nom, la navigation (Projets) et l'utilisateur avec sa déconnexion, puis le contenu ;
  - `PageHeader` : titre `h1`, sous-titre, zone d'actions ;
  - `DataNatureBanner` : nature des données, plus « Prototype de recherche, pas un dispositif médical » ;
  - `FormError` : message d'erreur du serveur sous un formulaire, `role="alert"` ;
  - `EmptyState`, `ConfirmDialog` (avec motif obligatoire si demandé), `DateTimeFr`, `NumberFr`.
- **Formulaires :**
  - toujours une Server Action avec `useActionState` ;
  - erreurs de champ sous le champ, erreur générale dans `FormError` ;
  - bouton d'envoi désactivé pendant l'envoi (`useFormStatus`) ;
  - libellés `<Label htmlFor>` ;
  - aucune validation scientifique côté client.
- **Tableaux :** composant `table` de shadcn/ui, nombres alignés à droite, état vide avec `EmptyState`.
- **Titres :** un seul `h1` par page (dans `PageHeader`) ; `h2` pour les sections et les onglets.
- **Chargement et erreurs :** `loading.tsx` et `error.tsx` par segment principal ; `not-found.tsx` en français.
