# C3 — Import des résultats et études d'exemple — Plan d'implémentation

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal :** un chercheur dépose un tableau de résultats (CSV/XLSX), corrige la correspondance des colonnes, voit les contrôles du moteur en français, puis enregistre l'import en une transaction, ou le retire plus tard. Chaque laboratoire peut créer en un clic l'étude d'exemple fictive et l'étude **réelle** Leslie et al. 2022 (Tableau S2, CC BY 4.0).

**Architecture :** le moteur Python reste la seule source des règles (`/tables/read`, `/mapping/suggest`, `/imports/check`, `/examples/*`). Le web :
- garde les octets déposés dans une zone temporaire côté serveur (`var/staging`), avec un jeton lié à (utilisateur, laboratoire, étude) ;
- relance le contrôle à l'enregistrement ;
- écrit le fichier dans un magasin adressé par contenu (`var/files/<sha256>`) ;
- enregistre `DataFile`, `ImportRun`, `Measurement`, `QcMeasurement` et `AuditEvent` dans une seule transaction Prisma.

Le dépôt passe par un **route handler** (pas une Server Action, limitée à 1 Mo).

**Tech Stack :** celle de C2 (Next.js 16.4, React 19, Prisma 7, PostgreSQL, Auth.js, shadcn/ui, Vitest + embedded-postgres), plus Python 3.12 pour la tâche 1 (`core/`, `engine/`, pytest).

**Spec :** `docs/superpowers/specs/2026-10-25-prototype-studio-design.md` : §3 (contrat du moteur, `existing`, jeu fictif), §5 (parcours d'import et précisions), §6 (onglet Imports, bouton d'étude d'exemple), §8 (réussite mesurable) et §11 (multi-laboratoires, étude réelle Leslie).

## Global Constraints

- **Toutes les contraintes globales de C2 s'appliquent** (`docs/superpowers/plans/2026-10-25-c2-socle-web.md`, « Global Constraints » et « Liste de contrôle de l'interface ») :
  - aucune règle scientifique en TypeScript ;
  - audit en ajout seul, écrit dans la même transaction ;
  - textes en français ;
  - nombres et dates au format `fr-FR` ;
  - un seul `h1` par page ;
  - composants partagés de `web/src/components/app/` ;
  - Server Action avec `useActionState` pour les formulaires.
- **Multi-laboratoires (§11)** :
  - chaque service reçoit un `LabContext` obtenu par `requireLab(labSlug, rôle)` ;
  - chaque requête filtre sur `laboratoryId` (directement ou par l'étude vérifiée) ;
  - un identifiant ou un jeton d'un autre laboratoire répond « introuvable » ;
  - chaque nouvelle fonction exportée d'un service est ajoutée à la suite `tenant-isolation.test.ts`, que son énumération des exports oblige à couvrir.
- **Écriture :** rôle `researcher` minimum.
- **Étude archivée :** lecture seule, refus « Étude archivée : lecture seule. ».
- **Fichiers :**
  - taille maximale 50 Mo (`MAX_BYTES` de B1) ;
  - au-delà : « Fichier trop volumineux (50 Mo maximum). », rien n'est enregistré ;
  - les octets ne transitent jamais par le navigateur après le dépôt : le navigateur ne manipule que le jeton.
- **Données personnelles :**
  - un contrôle qui renvoie `E_PII_COLUMN` ou `E_PII_VALUE` → rien n'est écrit dans le magasin ni en base, la zone de dépôt est effacée immédiatement ;
  - un `AuditEvent` `import.refused_pii` est créé avec les comptes d'issues **sans aucune valeur, nom de colonne ni nom de fichier**.
- **Répertoire de données :**
  - variable `MICROTRACE_VAR_DIR` (par défaut `<web>/../var` en développement, `/app/var` dans le conteneur, volume `files-data`) ;
  - sous-dossiers `staging/` et `files/`, créés à la demande.
- **Journaux :** jamais de valeur de cellule, de nom de colonne d'un fichier refusé, ni de jeton.

## Review Focus

1. Un même fichier enregistré deux fois, ou un double clic sur « Enregistrer l'import » → un seul import actif. Le second reçoit « Ce fichier a déjà un import actif dans cette étude. » (tâche 3).
2. Un jeton de dépôt d'un autre utilisateur, d'un autre laboratoire, d'une autre étude, expiré ou inventé → « Dépôt introuvable ou expiré. ». Rien n'est lu ni écrit (tâches 2 et 3).
3. Le moteur tombe entre le contrôle et l'enregistrement → « Le moteur d'analyse est indisponible. », rien n'est écrit, et le dépôt reste réutilisable pour réessayer (tâche 3).
4. Un import retiré puis le même fichier réimporté → accepté. Les mesures du retiré ne comptent plus dans `existing` (tâche 3).
5. Un fichier XLSX à plusieurs feuilles, ou dont une formule n'est pas calculée → choix de la feuille, ou erreur de lecture française du moteur, sans enregistrement (tâches 2 et 4).

### Tâche 2 : Zone de dépôt, magasin de fichiers et route de dépôt

**Files :**
- Create : `web/src/server/file-store.ts`, `web/src/app/(app)/labo/[labSlug]/etudes/[studyId]/imports/upload/route.ts`
- Test : `web/src/server/__tests__/file-store.test.ts`, `web/src/app/(app)/labo/[labSlug]/etudes/[studyId]/imports/__tests__/upload-route.test.ts`

**Interfaces :**
- Produces (`file-store.ts`, `server-only`) :
  - `varDir(): string`, à partir de `MICROTRACE_VAR_DIR`.
  - `putStaging(owner: { userId; laboratoryId; studyId }, file: { name; type; bytes: Uint8Array }) -> Promise<{ token: string; sha256: string; size: number }>` :
    - jeton de 32 octets aléatoires en base64url ;
    - écrit `staging/<token>.bin` et `staging/<token>.json` (propriétaire, nom d'origine, type, sha256, taille, `createdAt`) ;
    - au passage, purge les dépôts de plus de 24 h.
  - `readStaging(owner, token) -> Promise<{ bytes; name; type; sha256; size }>` :
    - lève `DomainError("Dépôt introuvable ou expiré.")` si le jeton est mal formé (`^[A-Za-z0-9_-]{43}$`), absent, expiré, ou si le propriétaire diffère (utilisateur, laboratoire **et** étude) ;
    - recalcule le sha256 et le compare aux métadonnées.
  - `deleteStaging(token)`.
  - `storeFile(sha256, bytes) -> Promise<string>` : écriture atomique (fichier temporaire puis renommage) dans `files/<sha256>` ; renvoie le chemin relatif ; ne réécrit pas un fichier existant.
  - `purgeStaging(now = new Date())`.
  - Route `POST …/imports/upload` (multipart, champ `file`, champ facultatif `sheet`) :
    - `requireLab(labSlug, "researcher")` ;
    - étude lue avec le filtre de laboratoire et non archivée ;
    - refus 413 au-delà de 50 Mo, d'après `Content-Length` **et** pendant la lecture du flux ;
    - `engineClient.readTable`, puis `putStaging` seulement si la lecture réussit ;
    - réponse JSON `{ token, table: TableRead }` ;
    - erreurs JSON `{ error: "<message français>" }` avec 4xx/503, jamais de détail interne ; le statut 503 correspond à `EngineUnavailableError`.
- [ ] **Étape 1 : tests qui échouent** :
  - **Magasin :**
    - aller-retour d'un dépôt ;

    - `storeFile` idempotent ;
    - aucun fichier temporaire restant ;

    - un slug non membre → 404 ;

    - un fichier de 50 Mo + 1 octet → 413 « Fichier trop volumineux (50 Mo maximum). », sans aucun dépôt écrit ;
    - une erreur de lecture du moteur (422) → son message français, sans aucun dépôt écrit ;
    - un succès renvoie le jeton et les colonnes.

### Tâche 3 : Services d'import (contrôle, enregistrement, retrait)

**Files :**
- Create : `web/src/server/imports.ts`
- Modify : `web/src/server/audit.ts` (lecture du journal : événements `ImportRun`), `web/src/lib/audit-labels.ts`
- Test : `web/src/server/__tests__/imports.test.ts`, `web/src/server/__tests__/tenant-isolation.test.ts` (couverture)

**Interfaces :**
- Consumes : `file-store.ts` (tâche 2), `buildStudyContext`, `loadWritable`, `ENGINE_TX_OPTIONS` (C2), `engineClient.suggestMapping` / `checkImport`.
- Produces :
  - `existingKeys(ctx, studyId) -> Promise<ExistingKey[]>` : clés des `Measurement` **et** `QcMeasurement` des imports `active` de l'étude, au format `ExistingKeyModel` du moteur.
  - `suggestStagedMapping(ctx, studyId, token, sheet?) -> Promise<Mapping>`.
  - `checkStagedImport(ctx, studyId, { token, sheet, mapping }) -> Promise<ImportResult>` :
    - contexte construit depuis la base, `existing` inclus ;
    - en cas d'issue `E_PII_COLUMN` ou `E_PII_VALUE` : `deleteStaging`, audit `import.refused_pii` (`after` = comptes par gravité et par code, rien d'autre), puis renvoi du résultat sans les records.
  - `saveImport(ctx, studyId, { token, sheet, mapping, acceptWarnings }) -> Promise<{ importRunId }>` :
    1. `readStaging` ;
    2. **nouveau** `checkStagedImport` (jamais le résultat du navigateur) ;
    3. erreurs → « Enregistrement impossible : le contrôle signale des erreurs. » ;
    4. avertissements sans acceptation → « Acceptez les avertissements pour enregistrer. » ;
    5. `storeFile` ;
    6. une transaction (`ENGINE_TX_OPTIONS` inutile, aucun appel au moteur dedans) qui :
       - relit l'étude modifiable ;
       - crée ou réutilise le `DataFile` (unique par étude et sha256) ;
       - refuse s'il existe un `ImportRun` actif pour ce fichier (« Ce fichier a déjà un import actif dans cette étude. », y compris sur la violation P2002 de l'index partiel) ;
       - crée l'`ImportRun` (contexte figé, versions des règles et du moteur, issues, compteurs, acceptation et auteur) ;
       - crée les `Measurement` et `QcMeasurement` (`createMany`, champs du record en camelCase) ;
       - écrit l'audit `import.create` (`after` : nom du fichier, sha256, nombre de lignes, compteurs) ;
    7. `deleteStaging`.
  - `retireImport(ctx, importRunId, reason)` :
    - motif rogné, obligatoire : « Le motif de retrait est obligatoire. » ;
    - import déjà retiré : « Import déjà retiré. » ;
    - audit `import.retire`.
  - `listImports(ctx, studyId)` : du plus récent au plus ancien, avec nom de fichier, statut, compteurs, auteur et date.
  - `getImport(ctx, importRunId)` : avec ses issues.
  - Libellés d'audit : `import.create` « Import enregistré », `import.retire` « Import retiré », `import.refused_pii` « Import refusé (données personnelles) ».
- [ ] **Étape 1 : tests qui échouent** (moteur simulé, base de test) :
  - **Enregistrement :**
    - un enregistrement propre crée le fichier, l'import, les mesures et l'audit, et efface le dépôt ;
    - le contrôle est relancé à l'enregistrement même si le navigateur envoie un autre résultat (le simulateur renvoie une erreur au second appel → refus, rien d'écrit) ;
    - erreurs → refus ;
    - avertissements sans acceptation → refus ; avec acceptation → succès et `warningsAccepted` renseigné.
  - **Doublons et réimport :**
    - même fichier deux fois → un seul actif, le second refusé ;
    - deux `saveImport` concurrents du même fichier → un seul succès ;
    - retrait puis réimport → accepté ;
    - les clés du retiré ne figurent plus dans `existingKeys`.
  - **Données personnelles :** aucun fichier dans `files/`, dépôt effacé, aucune ligne `DataFile`/`ImportRun`/`Measurement`, un audit sans valeur.
  - **Panne du moteur :** à l'enregistrement → `EngineUnavailableError`, rien d'écrit, dépôt conservé.
  - **Accès :** étude archivée et `viewer` refusés ; cas inter-laboratoires dans `tenant-isolation.test.ts`.

  - `…/imports/IssuesTable.tsx` ;
  - `…/imports/RetireButton.tsx`.
- Test : `…/imports/__tests__/*.test.tsx`

**Interfaces :**
- Consumes : la route de dépôt (tâche 2), les services de la tâche 3.
- Produces :
  - **Liste des imports** : fichier, date (`DateTimeFr`), auteur, lignes, erreurs, avertissements, statut (badge « actif » / « retiré » avec le motif). Bouton « Retirer » (`ConfirmDialog` avec motif obligatoire), absent pour un `viewer` ou une étude archivée. Si la liste est vide : `EmptyState`.
  - **Assistant** en quatre étapes visibles (« 1. Dépôt », « 2. Correspondance », « 3. Contrôle », « 4. Enregistrement ») :
    1. **Dépôt** : `fetch` vers la route de dépôt ; affichage de la taille, des feuilles (choix si plusieurs) et d'un aperçu des 20 premières lignes.
    2. **Correspondance** :
       - formulaire prérempli par `suggestStagedMapping` ;
       - mode long ou large ;
       - pour chaque champ du dictionnaire, une colonne ou une constante ;
       - colonnes de polymères (mode large) ;
       - case « Séparer les aliquotes (suffixe a/b) ».
       La liste des champs vient du type `MappingModel` / dictionnaire du moteur, pas d'une liste recopiée.
    3. **Contrôle** :
       - table des issues filtrable par gravité et par code : gravité, code, ligne, colonne, champ, message ;
       - compteurs en tête ;
       - aucun enregistrement à cette étape.
    4. **Enregistrement** :
       - bouton désactivé s'il y a des erreurs ;
       - case « J'ai lu les avertissements et je les accepte » obligatoire s'il y a des avertissements ;
       - après succès, retour à la liste.
  - L'état de l'assistant (jeton, feuille, correspondance) vit côté client. Chaque action serveur relit le dépôt par le jeton.
