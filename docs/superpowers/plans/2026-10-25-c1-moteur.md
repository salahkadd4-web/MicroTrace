# C1 — Moteur scientifique (microtrace_engine) — Plan d'implémentation

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal :** un service FastAPI sans état, local et protégé par un secret, qui expose B1 (`microtrace_core.results`) en JSON à l'application Next.js : lecture de fichier, correspondance, contrôle d'import (y compris la cohérence avec les mesures déjà enregistrées), synthèse, rapport, dictionnaire et jeu fictif.

**Architecture :** nouveau composant `engine/` (package `microtrace_engine`, layout `src/`, comme `core/`).
- `schemas.py` : modèles Pydantic qui sont l'image exacte des dataclasses de B1.
- `convert.py` : conversion dans les deux sens.
- `crossimport.py` : règles de cohérence entre imports, écrites en Python à partir des fonctions de B1.
- `report.py` : rapport Markdown/HTML, sans dépendance web.
- `app.py` : les routes.

Aucune base de données, aucun fichier écrit. Le moteur ne journalise jamais le contenu des cellules.

**Tech Stack :** Python ≥ 3.12, FastAPI, Uvicorn, python-multipart, Pydantic v2, httpx (tests), pytest ; B1 en dépendance éditable.

**Spec :** `docs/superpowers/specs/2026-10-25-prototype-studio-design.md` (§3 contrat et formes JSON, §5 parcours, §8 réussite). Règles scientifiques : `docs/superpowers/specs/2026-10-24-microtrace-studio-v0-design.md` §5.

## Global Constraints

- `microtrace_engine` dépend de `microtrace-core` ; il n'importe jamais `microtrace_ml` ; il ne réimplémente aucune règle de B1 (il appelle ses fonctions). Seules les règles de cohérence entre imports (tâche 5) sont nouvelles, et elles réutilisent `issue()` et les codes de B1.
- Dépendances : `fastapi>=0.115`, `uvicorn>=0.30`, `python-multipart>=0.0.9`, `pydantic>=2.7` ; dev : `pytest>=8`, `httpx>=0.27`. Installation : `.venv/Scripts/python -m pip install -e "engine[dev]"`.
- Sérialisation : enums → valeur texte ; `Unit` → son code (`"ug/mL"`) ; tuples → listes ; nombres non finis interdits (B1 les refuse déjà).
- Sécurité :
  - chaque route sauf `GET /health` exige l'en-tête `X-Engine-Secret` égal à la variable d'environnement `ENGINE_SECRET` (comparaison en temps constant) ; secret absent → 401, en français ;
  - le service refuse de démarrer si `ENGINE_SECRET` est vide ou fait moins de 32 caractères ;
  - écoute par défaut sur `127.0.0.1:8001`.
- Taille des fichiers reçus : refus au-delà de `MAX_BYTES` de B1, avant toute lecture complète en mémoire supplémentaire.
- Erreurs : `TableReadError` et `ValueError` de B1 → 422 `{"detail": "<message français>"}`. Aucune trace de pile, aucune valeur de cellule dans les réponses d'erreur ni dans les journaux.
- Tests : uniquement des données synthétiques ; commandes `.venv/Scripts/python -m pytest engine/tests -q -W error` et suite rapide `.venv/Scripts/python -m pytest -q -W error -m "not data"` (`pytest.ini` : ajouter `engine/tests` à `testpaths`).
- Commits conventionnels terminés par `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.

## Review Focus

1. **Aller-retour fidèle** : records → JSON → records doit être identique (valeurs `None`, flottants, `Unit`, enums, `source_row`). → `test_record_roundtrip_leslie` (tâche 3).
2. **Secret** : une route sans en-tête, avec un mauvais secret ou avec un secret vide → 401 ; `/health` accessible sans secret mais ne révèle rien de sensible. → `test_secret_required_everywhere` (tâche 2).
3. **Données personnelles dans les journaux** : importer un fichier contenant « jean.dupont@chu.fr » et « 06 12 34 56 78 » avec la capture des journaux activée → aucune occurrence dans `caplog.text` ni dans la réponse. → `test_no_cell_values_in_logs_or_errors` (tâche 7).
4. **Cohérence entre imports** : un enregistrement identique à une mesure existante, ou un échantillon existant avec une autre matrice → erreur ; un nouvel échantillon → aucune issue. → tests de la tâche 5.
5. **Fichiers volumineux et feuilles** : un XLSX à plusieurs feuilles renvoie la liste des feuilles ; un fichier > `MAX_BYTES` → 422 sans lecture. → tests de la tâche 4.

**Interfaces :**
- Produces :
  - `ExistingKeyModel(sample_id, aliquot, record_type, polymer, method, matrix, matrix_detail)`.
  - `POST /imports/check` (multipart : `file`, `sheet`, `mapping` (JSON), `context` (JSON), `existing` (JSON, liste, facultatif)) → `ImportResultModel`.
  - `cross_import_issues(records, existing) -> list[Issue]` :
    - `E_DUPLICATE_RECORD` (error) pour un record dont la clé (`sample_id`, `aliquot`, `record_type`, polymère, méthode normalisée comme dans B1) existe déjà ; message « déjà enregistré dans un import actif de l'étude », `row` = `source_row`, `column`/`field` comme les doublons de B1 ;
    - `E_SAMPLE_CONFLICT` (error) quand un `sample_id` existant porte une autre matrice, un autre détail de matrice « other » ou un autre `record_type` (un seul issue par échantillon).
  - Si ces issues existent, le résultat renvoyé a `records == []`, `qc_records == []` et `has_errors == true` (même règle que B1 : une erreur bloque tout).
  - Le résultat expose `has_errors` et les compteurs par gravité.
